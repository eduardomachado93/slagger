**Slagger** (Slim + Swagger) automatically produces compliant **OpenAPI 3.0** specifications and serves an interactive **Swagger UI** for [Slim Framework 4](https://www.slimframework.com/) applications using native PHP 8 Reflection and Attributes.

---

## Features

- 🚀 **Zero Heavy Annotations**: Powered exclusively by native PHP 8 Attributes (`ReflectionAttribute`) and standard PHP reflection.
- 🧩 **Deep DTO Introspection**: Maps typed PHP properties, nullability, and required attributes directly to OpenAPI schema components.
- ⚡ **Dynamic Slim 4 Route Extraction**: Automatically parses FastRoute regex constraints (e.g. `{id:[0-9]+}`) into standard OpenAPI path parameters.
- 🛡️ **Graceful Fallbacks**: Works out of the box even with anonymous closures or unannotated controllers with zero runtime errors.
- 🎨 **Built-in Swagger UI**: Embedded PSR-15/callable handler serving the official Swagger UI directly via unpkg CDN.
- 🔒 **Type-Safe**: Developed with `declare(strict_types=1);` and verified at **PHPStan Level 8**.

## Installation

Install via Composer:

```bash
composer require eduardomachado93/slagger
```

You will also need a PSR-7 implementation in your Slim 4 project (e.g., `nyholm/psr7` or `slim/psr7`):

```bash
composer require nyholm/psr7 nyholm/psr7-server
```

## Quick Start

### 1. Define Your DTOs and Controllers

Use PHP 8 native attributes to document your request payloads and responses:

```php
<?php

declare(strict_types=1);

namespace App\DTO;

final class CreateUserDto
{
    public string $name;
    public string $email;
    public ?int $age = null; // Nullable -> optional in OpenAPI schema
}
```

Annotate your controller methods:

```php
<?php

declare(strict_types=1);

namespace App\Controllers;

use App\DTO\CreateUserDto;
use Psr\Http\Message\ResponseInterface;
use Psr\Http\Message\ServerRequestInterface;
use Slagger\Attributes\ApiResponse;
use Slagger\Attributes\RequestBody;
use Slagger\Attributes\Tag;

#[Tag(name: 'Users', description: 'User management operations')]
final class UserController
{
    #[Tag(name: 'Users')]
    #[ApiResponse(status: 200, dtoClass: CreateUserDto::class, description: 'User found')]
    #[ApiResponse(status: 404, description: 'User not found')]
    public function get(ServerRequestInterface $request, ResponseInterface $response): ResponseInterface
    {
        // your logic
        return $response;
    }

    #[Tag(name: 'Users')]
    #[RequestBody(dtoClass: CreateUserDto::class, description: 'New user data payload')]
    #[ApiResponse(status: 201, dtoClass: CreateUserDto::class, description: 'User created successfully')]
    #[ApiResponse(status: 400, description: 'Invalid input data')]
    public function create(ServerRequestInterface $request, ResponseInterface $response): ResponseInterface
    {
        // your logic
        return $response->withStatus(201);
    }
}
```

### 2. Mount Slagger in your Slim 4 Application

Register routes and enable Swagger UI documentation:

```php
<?php

declare(strict_types=1);

use App\Controllers\UserController;
use Nyholm\Psr7\Factory\Psr17Factory;
use Slagger\Slagger;
use Slim\Factory\AppFactory;

require __DIR__ . '/vendor/autoload.php';

$psr17Factory = new Psr17Factory();
AppFactory::setResponseFactory($psr17Factory);
$app = AppFactory::create();

// Define API routes
$app->get('/users/{id:[0-9]+}', [UserController::class, 'get']);
$app->post('/users', [UserController::class, 'create']);

// Closure routes are also supported with automatic fallback specs
$app->get('/health', function ($request, $response) {
    $response->getBody()->write(json_encode(['status' => 'healthy']));
    return $response->withHeader('Content-Type', 'application/json');
});

// Configure Slagger
$slagger = new Slagger(
    app: $app,
    title: 'My Slim 4 API',
    version: '1.0.0',
    description: 'Interactive API Documentation generated by Slagger'
);

// Register OpenAPI JSON (/openapi.json) and Swagger UI (/docs)
$slagger->register(
    jsonPath: '/openapi.json',
    uiPath: '/docs'
);

$app->run();
```

Navigate to `http://localhost:8080/docs` in your browser to explore your Swagger UI!

## Native Attributes Reference

| Attribute | Target | Arguments | Description |
| :--- | :--- | :--- | :--- |
| `#[Tag]` | Class, Method | `string $name`, `string $description = ''` | Assigns an OpenAPI tag group to the endpoint. |
| `#[RequestBody]` | Method | `string $dtoClass`, `string $description = ''` | Documents request body schema via DTO inspection. |
| `#[ApiResponse]` | Method (Repeatable) | `int $status`, `?string $dtoClass = null`, `string $description = 'OK'` | Documents HTTP response codes and optional DTO schemas. |

## Architectural Overview

Slagger is designed with strict boundaries and zero framework bloat:

```text
src/
├── Attributes/       # Pure declarative metadata (Native PHP 8 Attributes)
├── Extractor/        # Reads route definitions from Slim RouteCollector
├── Inspector/        # Resolves callables (array, string, invokable) to ReflectionMethod
├── Parser/           # Pure string/regex converter for FastRoute parameters
├── Schema/           # Maps typed DTO properties to OpenAPI 3.0 schema definitions
├── Ui/               # PSR-15/callable action serving Swagger UI HTML via unpkg CDN
└── Slagger.php       # Root orchestrator assembling the complete OpenAPI 3.0 spec
```
